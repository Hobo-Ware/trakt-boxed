# i18n Guidelines

## Source of truth

trakt-boxed dropped the `i18n/meta/` source layer that trakt-web had.
Paraglide JS reads `i18n/messages/{locale}.json` directly via the
`@inlang/plugin-message-format` plugin. There is no compile step
producing those files — they ARE the source.

- Base locale: `en`. Edit `projects/client/i18n/messages/en.json`
  first when you add a key.
- Then propagate. The other 20 locales must carry the same key set;
  paraglide's `without-source` and `missing-translation` lint rules
  will flag drift, and the generated `lib/paraglide/messages.js` will
  stop including the key for any locale that lacks it.

## Sync workflow

A helper script lives at `projects/client/scripts/sync-i18n.ts`. Two
modes:

```
deno task i18n:check   # CI gate — exits non-zero if any locale drifts
deno task i18n:sync    # writes English fallbacks for missing keys
```

`i18n:sync` is the recommended path after adding keys to `en.json`.
It fills missing keys with the English value as an explicit fallback
so translators can see exactly which surfaces still need their
attention without breaking the build.

Run `i18n:check` from CI before deploy. Drift is a hard fail.

## Translation policy

For any new user-visible string:

1. Author the English in `en.json` and `en-au.json` (the Australian
   variant is what trakt-web localizes to first).
2. Provide real translations for the priority languages:
   `de-de`, `fr-fr`, `fr-ca`, `es-es`, `es-mx`, `it-it`, `pt-br`,
   `nl-nl`, `ja-jp`, `zh-cn`, `ru-ru`, `pl-pl`.
3. Leave the remaining locales — `bg-bg`, `da-dk`, `nb-no`, `ro-ro`,
   `sv-se`, `tr-tr`, `uk-ua` — as explicit English fallbacks (do not
   omit the key, that breaks parity). `i18n:sync` does this for you
   if you skip them.

## Naming conventions

Keys are `snake_case`, prefixed by surface:

- `button_label_*`, `button_text_*` — button accessibility label and
  visible text respectively.
- `link_text_*` — visible link text.
- `text_*` — body copy.
- `header_*` — section headings.
- `list_title_*` — list section titles.
- `eyebrow_*` — the lowercase tracked verb chip used by
  `.summary-eyebrow`.
- `page_title_*` — `<title>` text.

Never use `i18n:` or `wip:` as a commit prefix; conventional commits
only. Sweep i18n changes into the feature commit they support, not as
a standalone "translations" commit unless you literally only updated
translations.
